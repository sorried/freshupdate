# как запустить своего бота

если нужны только уведомления, установка не требуется: открой [@freshupdbot](https://t.me/freshupdbot) и отправь `/start`. эта инструкция для запуска отдельного бота со своим токеном.

бот должен постоянно работать на компьютере или сервере с доступом к telegram и github. домен, https-сертификат и открытые входящие порты не нужны.

## 1. создай бота

открой [@BotFather](https://t.me/BotFather) в telegram, отправь `/newbot` и следуй его подсказкам. полученный токен понадобится при настройке. не публикуй его и не отправляй в issue.

## 2. скачай проект

нужен git. команды ниже рассчитаны на linux.

```bash
git clone -b dev https://github.com/sorried/freshupdate.git
cd freshupdate
cp .env.example .env
chmod 600 .env
```

открой `.env` в текстовом редакторе и укажи токен после `BOT_TOKEN=`. для отслеживания freshGram остальные настройки можно оставить как есть.

## 3. запусти

выбери один способ. не запускай docker и обычный процесс одновременно с одним токеном.

### через docker

нужны установленный docker engine и плагин docker compose. node.js отдельно не требуется.

из каталога проекта выполни:

```bash
docker compose up -d --build
docker compose logs -f bot
```

`Ctrl+C` закрывает просмотр логов, бот остаётся работать в фоне. контейнер настроен на автоматический перезапуск, но сам docker должен запускаться при загрузке сервера.

остановить бота:

```bash
docker compose stop
```

обновить код и запустить новую версию:

```bash
git pull
docker compose up -d --build
```

данные хранятся в docker volume `bot-data` в файле `/app/data/bot.db` внутри контейнера. пересборка их не удаляет. не выполняй `docker compose down -v`: это удалит базу с подписчиками и историей рассылок.

### без docker

нужны node.js 22+ и npm.

```bash
npm ci --ignore-scripts
npm run build
npm start
```

запускай команды из каталога проекта. бот работает, пока запущен процесс; `Ctrl+C` его останавливает. база хранится в `data/bot.db`.

для постоянной работы на linux-сервере есть [пример systemd-сервиса](deploy/freshupdate.service). он рассчитан на пользователя и группу `freshupdate`, каталог `/opt/freshupdate` и node.js в `/usr/bin/node`. перед установкой создай пользователя, размести проект по этому пути, собери его и настрой `.env`. создай каталог `/opt/freshupdate/data` с правом записи для пользователя сервиса; ему также нужен доступ на чтение файлов проекта и `.env`. при других путях измени файл сервиса.

после подготовки, из каталога проекта:

```bash
sudo install -m 644 deploy/freshupdate.service /etc/systemd/system/freshupdate.service
sudo systemctl daemon-reload
sudo systemctl enable --now freshupdate
sudo journalctl -u freshupdate -f
```

при обновлении выполни `git pull`, `npm ci --ignore-scripts`, `npm run build` и `sudo systemctl restart freshupdate`. не запускай параллельно `npm start`.

## 4. проверь работу

открой своего бота в telegram и отправь `/start`. он должен ответить приветствием. каждый пользователь включает уведомления отдельно в личном чате с ботом.

при первом запуске бот запоминает существующие релизы, не рассылая их. уведомления появятся при обнаружении новых публикаций. по умолчанию проверка выполняется каждые 5 минут, включая предварительные версии.

## настройки

настройки находятся в `.env`. после изменения перезапусти бота. для docker используй `docker compose up -d`, чтобы применить изменённое окружение.

| переменная | по умолчанию | назначение |
| --- | --- | --- |
| `BOT_TOKEN` | не задан | обязательный токен твоего бота |
| `GITHUB_REPOSITORY` | `Snowy-Fluffy/freshGram` | репозиторий для проверки релизов |
| `CHECK_INTERVAL_SECONDS` | `300` | интервал проверки в секундах |
| `INCLUDE_PRERELEASES` | `true` | `false`, чтобы получать только стабильные релизы |
| `DATABASE_PATH` | `data/bot.db` | путь к базе при запуске без docker |
| `GITHUB_TOKEN` | не задан | необязательный токен для увеличения лимита запросов github |

в docker путь к базе фиксирован в `compose.yaml`. для другого репозитория используй отдельную базу; тексты и кнопки бота рассчитаны на freshGram.

## если не запускается

- проверь `BOT_TOKEN` в `.env` и доступ к telegram и github.
- убедись, что с этим токеном не работает другая копия бота.
- если бот раньше использовал webhook, отключи его через telegram bot api `deleteWebhook`. приложение само его не удаляет.
- при ошибке доступа к базе проверь права записи в каталог `data/` для пользователя процесса.
- после аварийной остановки блокировка базы может сохраняться до 2 минут. подожди перед повторным запуском.

не удаляй базу ради перезапуска: в ней подписчики и история отправленных релизов. перед резервным копированием останови бота и сохрани весь каталог `data/` или docker volume. `.env` с токеном храни отдельно от публичного кода.
